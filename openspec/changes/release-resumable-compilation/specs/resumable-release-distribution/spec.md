## Purpose

让通过普通 Composer 或原生安装入口取得构建器的使用者获得同一版本的断点续编功能，并使发行资产、资源摘要与实际安装运行时可被独立核验，避免只有源码具备功能而公开安装继续使用旧运行时。

## ADDED Requirements

### Requirement: 同版安装绑定

发行系统 SHALL 将 Composer 0.4.0 与原生 0.4.0 完整包绑定；首次普通安装仍提供现有选择菜单，安装后的构建器默认保留已验证对象并通过同一入口重试恢复。

#### Scenario: 首次 Composer 安装
- **WHEN** 用户安装 0.4.0 Composer 包并选择准备组件
- **THEN** 下载并校验 0.4.0 完整包，实际安装版本为 0.4.0，随后可选择项目与构建

### Requirement: 实际发行材料身份

发行系统 MUST 从实际制作的双平台组件、安装包与 setup 得出锁定摘要和大小，拒绝不匹配资源；旧发行资产 SHALL 保持不可变。

#### Scenario: 新组件包装
- **WHEN** 制作 0.4.0 组件与完整安装包
- **THEN** 包内锁与新增 TypePHP 补丁摘要匹配，Composer 和 setup 的大小及摘要与实际归档一致

#### Scenario: 损坏下载
- **WHEN** 实际下载与发行资源摘要不符
- **THEN** 安装拒绝使用，报告可重试的失败，既有已安装运行时不被错误替换

### Requirement: 发行证据分层

发行记录 SHALL 区分源码、归档、安装、原生执行与物理平台验证；公开命令与市场说明 MUST 使用当前实际发行入口，并明确不能在单个未完成单元内部续跑。

#### Scenario: 平台未实测
- **WHEN** Windows 归档已制作而 Windows 执行验收未运行
- **THEN** 记录归档通过及执行门槛缺口，不将其描述为 Windows 运行验证通过
