## Why

使用者在 Windows 与 macOS 从源码制作工具安装包时，必须复制多段命令、识别下载符号和 JSON，并自行串联校验、安装及项目构建。工具应承担这些可自动完成的步骤，让使用者执行一个文件，仅选择包类型、安装与项目目录，并看懂成功、失败及下一步。

## What Changes

- 增加源码根目录 Windows `.cmd` 与 macOS `.command` 引导入口，选择轻量/完整包后自动准备锁定材料、构包、校验和隔离安装自检。
- 直接安装提供独立单文件 setup 入口，选择轻量/完整后自动下载版本锁定安装包、核验外层摘要、解压并进入安装；使用者无需对照资产或手工解压。
- 安装包仍包含原生启动文件供离线/已持有包使用，确认安装后调用已有安装器，验证新安装并进入下一步菜单。
- 同一流程允许选择 Webman/SaiAdmin 项目目录，自动调用现有 build 与 verify，显示产物位置和验证范围。
- 整合项目镜像源码快照修复：任意层 `.DS_Store` 不触发源码变化误判；真实源码新增、删除、修改仍阻断并显示具体相对路径，新安装包包含该修复。
- 所有阶段显示人话、实时状态、真实错误、可执行恢复建议和 Issues 地址；现有自动化参数、JSON 协议与离线保证保持兼容。

## Capabilities

### New Capabilities
- `guided-build-install`: 源码构包、安装包安装以及选择项目构建验证的一次启动交互流程。

### Modified Capabilities

无；本项目首次采用 OpenSpec。

## Impact

涉及 tools 构包入口、installer 原生启动文件、package-installers 资产收集、共享 PHP 引导逻辑、项目镜像/源码快照、材料锁、直接相关测试和 README/Wiki 使用入口。复用已有下载器、锁文件、安装器及 CLI，不引入 GUI、新下载框架、自动部署或服务控制。开发验证只操作任务私有安装目录和隔离项目；用户后续明确授权同feature分支提交、推送、PR及原生Windows CI必要修复；真实用户安装、合并、Release、部署与Wiki发布不在该授权内。
